1\. Data Quality Impact  
Describe a specific data quality issue you encountered in the supplied data. How did your cleaning decision change the outcome of your analysis? What would have happened if you had not caught it?  
**A specific data quality issue that was encountered in the supplied data was with the SKU that the data gave us. For example in the strawberry Pop-Tarts there were 4 SKUs (PT-12, SKU\#459812, POPTART-STRAW, PT\_STRAWBERRY) for the same item. Because of this data quality issue we decided to consolidate the SKUs together into a single SKU to help prevent any fragmentation in the data, that would cause us from getting a true overview of which items showed a real demand. Because of this consolidation we were able to see a real demand for strawberry Pop-Tarts where there was a 9.2x increase from relative value or a \+410% increase, had we decided to not have consolidated the SKU we would have never been able to see such large increase due to data fragmentation which would have hidden such data from us.**

2\. ETL Trade-offs  
You made choices about how to standardize SKUs, handle missing timestamps, and join weather data. Pick one decision and explain: what alternative approach could you have taken, and how might it have changed your results?  
**During our ETL cleaning when we had missing timestamps we decided to drop it based on five possible ways to be null (‘blank’/’NULL’/’N/A’/’nan’/’’). This lead us to drop a total of 881 rows from the data set due to missing timestamps which we decided was a small amount of data set to remove while also helping to reduce issues from arising such as when running models or analysis to know the exact optimal time to restock as with our weather analysis having the null value can skew out results as we don’t know if it was before or after or during the storm. Had we decided to keep the missing timestamp in our data set we would have reached issues that could possibly made our analysis unreliable a big issue would be in our weather and correlation analysis we determined that 2 days before the storm had the strongest correlation, however if we included the missing timestamp we would have had to guess where it falls under before, after, or during and those data points while small compared to the entire data set still has the ability to skew our results making it unreliable.**

3\. Pipeline Trust  
The Walmart CDO argued that the biggest risk is not the model — it is the pipeline. Based on your experience in this project, do you agree or disagree? What was the most fragile part of your data pipeline?  
**I would agree with the Walmart CDO that the biggest risk is the pipeline was the weather API. Since we got it from Open-Meteo historical weather API, there are some parts of the API that makes it fragile. Some are since it is a free API we are rate limited and we also have lagging data, while this does not affect us as we are dealing with a weather that has already passed. This could be a large issue when testing the correlation models with real time data as it would require constant API calling which would make us rate limited. Some other issues are how the data is given to us; it is stamped to GMT however we had one store (FL-710) that was in CST and the rest was in EST and the data was hourly weather data. Due to this we had to create an offset and convert to the correct timezone to be able to accurately track the data. Because of these issues it is the most fragile part of our data pipeline as we needed to clean the weather data in order for it to be accurate and we are limited on how fast and real time the data can be as it was based on GMT or CST which needed to be offset to get the correct timestamps.** 

4\. Business vs. Data

**Our team decided to weigh the statistical evidence if there is multiple correlation that helps to support our reasoning. We recommended restocking the shelves with board games as we had three strong pieces of evidence that supported it as a signal: There was no category lumping, more than one system agreed, and shelves emptied when sales surged. Since these were three strongly supporting evidence it allowed us to make a recommendation to restock. We might have decided differently given more time or more data as a caveat with the analysis was there was only three SKUs and about 7-14 sampled inventory rows a day, this is a small sample size which might be the reason why it is shown as a signal had we had more data points to measure we might change our decision as it might become an artifact and not a signal.**
